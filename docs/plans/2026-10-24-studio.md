# policyproof milestone 5 (the studio): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `policyproof studio DOC.md` opens a local page where a business author walks through every problem in the
policy extracted from their document, as example customers in plain English, accepts checked changes, and ends with a
document, a policy and approved examples that agree.

**Architecture:** Python owns all the logic. `policyproof.studio` has pure modules (`workspace` for the files, `wire`
for the API's JSON shapes, `view` for the document as the page shows it, `items` for every finding in the same
style), a `session` that runs the operations over the M4 authoring layer, and a Starlette `server` that is the only
module importing a web library. The API's JSON Schema is generated from `wire` and committed; the TypeScript types
are generated from it, and every response is validated against it on arrival. The UI under `studio/` is React with an
Elm-style loop: one immutable state, a pure `update(state, msg)` returning the next state and commands as data,
views as pure functions, `useReducer` only.

**Tech Stack:** Python >= 3.13, Starlette + uvicorn (`[studio]` extra), pydantic (schema generation and request
parsing in `studio.schema` and `studio.server` only). TypeScript 5, React 18, Vite, Vitest, fast-check, Ajv (the
schema library: it validates against the very JSON Schema the types come from), json-schema-to-typescript.

**Spec:** `docs/specs/2026-10-24-studio-design.md` (with "Calls made after the design review") and the prototype
`docs/specs/assets/2026-10-24-studio-prototype.html`, whose layout, wording, CSS and flow the page follows. M4's plan
`docs/plans/2026-10-24-authoring.md` lists what it left for this milestone.

## Global Constraints

- Everything from M4's Global Constraints still holds (style, `Result`s, no exception across a port, ty and ruff
  clean, line length 120, commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`).
- **No paid model call** in any test or check. Every model-facing path is tested with `tests/authoring_fakes.py`.
- The server binds to **127.0.0.1 only** and every `/api/` request needs the per-run token (query `?t=` or header
  `X-Studio-Token`); a wrong or missing token is 403.
- No formula, variable name or solver word outside "Show the logic" (spec anti-goals). Variables appear through
  their display phrases or descriptions; rules as their sentences; outcomes through `outcome_label`.
- Nothing is written unchecked: a policy change reaches disk only through `accept` of a checked proposal, or through
  a pure, typechecked operation (merging two names, removing an unused name). Every write is undoable.
- Files are written on every accept; there is no Save (spec Calls 3). A `SolverGaveUp` is an item, never a pass.
- `[studio] = ["pydantic-ai-slim>=2.54", "starlette>=0.47", "uvicorn>=0.35"]`. Only `policyproof.studio.server`
  and `policyproof.studio.cli` import starlette or uvicorn; `workspace`, `wire`, `view`, `items` import no pydantic,
  no web library and no model SDK.
- The built page ships inside the package at `src/policyproof/studio/static/`; authors don't need Node.

## Builder's calls (spec "What's left to the builder")

- **Web server:** Starlette with uvicorn; tests use Starlette's `TestClient`.
- **TS schema library:** Ajv over the generated `api.schema.json`; types from json-schema-to-typescript. One
  definition, the Python `wire` dataclasses.
- **Model configuration:** `--model MODEL` (a pydantic-ai model string) for the extractor, drafter and phraser.
  Without it the studio opens an existing policy and offers everything that needs no model; operations that need
  one say "Start the studio with --model to …".
- **File names:** `NAME.md`, `NAME.policy.yaml`, `NAME.examples.yaml` (M4's examples format) and the workspace
  `.NAME.studio/` holding `workspace.yaml` (links, uncovered, background, dismissed, fixed, baseline document) ,
  `snapshot.yaml` (the last full extraction, for "Extract again") and `undo/0001.yaml`… (each the previous four
  files' text).
- **File watching:** the page polls `GET /api/outside` every 2 s; the server compares the document's content hash
  with the last text it read or wrote, so its own writes never count.
- **Retries:** proposals keep M4's default of 2 retries. **Debounce** on "Edit the wording": 400 ms.
- **Rule numbers:** the page numbers the sentences that have rules, in document order; "Rule 4" is the rule from
  sentence 4. A rule with no sentence is "a rule not in your document".
- **Groups:** a group of problems that share rules is decided with one question per customer ("What should each of
  these customers get?") and one proposal for all of them; "Decide each one separately" splits it. The prototype's
  LLM-written group question is not reproduced; the per-customer form is deterministic and offers the same choices.
- **Tracked changes:** sentences are compared with the baseline document (the text when the studio last extracted
  in full); a changed sentence shows a word diff against its closest baseline sentence in the same section.

## Review Focus

1. **A stale proposal accepted after the policy moved on** (two tabs, or an undo between propose and accept): accept
   must refuse a proposal made on an older version, not write it over the newer one
   (`test_accepting_a_stale_proposal_is_refused`, Task 5).
2. **An outside edit while a proposal is open:** the next accept refuses and the page offers "Extract again"; the
   author's editor change is never overwritten (`test_accept_refuses_when_the_document_changed_on_disk`, Task 5).
3. **Undo past the start, and undo after a restart:** undo with no history is a clear error; history on disk survives
   a new `Session` (`test_undo_survives_a_restart`, Task 2; `test_undo_with_no_history_is_an_error`, Task 5).
4. **A dismissed warning whose rules change:** it comes back with its old reason shown
   (`test_a_dismissal_lapses_when_its_rules_change`, Task 4).
5. **A server response that doesn't match the schema** (an old page against a newer server): the page shows an error,
   never renders half a state (`test_a_malformed_response_is_an_error`, Task 7).
